# knowledge-base Specification

## Purpose
Формат, загрузка и проверка целостности базы знаний (FAQ и карточки товаров), детерминированное представление базы для модели.

## Requirements

### Requirement: Формат базы знаний
Система SHALL читать базу знаний из файла `knowledge_base.json`, содержащего поле `version` и список `entries`. Каждая запись MUST иметь уникальный `id`, `type` (`faq` или `product`), `title` и `content`. Запись типа `product` MUST дополнительно иметь `price` (целое число, рубли), `pitch` (согласованная фраза для допродажи) и `related_ids` (список id товаров, может быть пустым); поле `contraindications` у товара необязательно.

#### Scenario: Корректная база загружается
- **GIVEN** файл базы с 5 записями `faq` и 9 записями `product`, все поля заполнены корректно
- **WHEN** сервис запускается
- **THEN** база загружена, доступны 14 записей и значение `version` из файла

#### Scenario: У товара нет обязательного поля
- **GIVEN** в файле базы запись `product` без поля `pitch`
- **WHEN** сервис запускается
- **THEN** запуск завершается ошибкой с указанием id записи и отсутствующего поля

### Requirement: Целостность ссылок в базе
Система SHALL при загрузке проверять, что все `id` уникальны и каждый элемент `related_ids` ссылается на существующую запись типа `product`, отличную от самой записи.

#### Scenario: Ссылка на несуществующий товар
- **GIVEN** у товара `omega3_1000` в `related_ids` указан `unknown_product`
- **WHEN** сервис запускается
- **THEN** запуск завершается ошибкой, в сообщении указаны `omega3_1000` и `unknown_product`

#### Scenario: Повторяющийся id
- **GIVEN** две записи базы с одинаковым `id`
- **WHEN** сервис запускается
- **THEN** запуск завершается ошибкой с указанием повторяющегося `id`

### Requirement: Стабильное представление базы для модели
Система SHALL формировать текст базы для системного промпта детерминированно: одинаковый файл базы MUST давать побайтно одинаковый текст (фиксированный порядок записей и полей, без дат и идентификаторов запроса).

#### Scenario: Повторная сборка промпта
- **GIVEN** загруженная база знаний
- **WHEN** текст базы для промпта собирается дважды
- **THEN** обе строки побайтно совпадают

### Requirement: Тексты базы проходят стоп-лист
Тексты базы (`content`, `pitch`, `contraindications`) MUST NOT вызывать срабатывание стоп-листа медицинских обещаний; это проверяется автоматическим тестом.

#### Scenario: Проверка базы стоп-листом
- **GIVEN** загруженные база знаний и стоп-лист
- **WHEN** каждое текстовое поле каждой записи проверяется стоп-листом
- **THEN** ни одного срабатывания нет
