## Why

Сейчас сервис принимает уже собранный JSON (`message` + `history`), и кто-то должен вручную переносить сообщения из AmoCRM и обратно. Чтобы менеджер видел черновик и подсказку прямо в сделке, нужен адаптер: принять сообщение из чата сделки, накопить историю диалога и записать результат во внутреннее примечание. Реального аккаунта amoCRM на время тестового нет, поэтому адаптер должен работать в mock-режиме, а подключение к настоящей amoCRM сводиться к настройке `.env`.

## What Changes

- Эндпоинт `POST /webhooks/amo?token=…` принимает вебхук в формате, приближенном к событию amoCRM «новое сообщение в чате» (`application/x-www-form-urlencoded`, `message[add][0][…]`). Отвечает сразу, генерация идёт в фоне.
- Роли: входящее сообщение (`type=incoming`) — клиент, исходящее (`type=outgoing`) — менеджер. Черновик генерируется только на сообщение клиента; сообщение менеджера только пополняет историю.
- Хранилище диалогов в памяти по `lead_id`: история, дедупликация по id сообщения, товары, уже предложенные в прошлых подсказках.
- Интерфейс `CrmClient` с методом записи примечания к сделке: `MockCrmClient` (по умолчанию, примечания в памяти) и `AmoCrmClient` (запись через REST API amoCRM `POST /api/v4/leads/{id}/notes` с долгосрочным токеном). Режим выбирается `CRM_MODE=mock|amo`.
- Результат — только внутреннее примечание к сделке: черновик ответа клиенту и подсказка менеджеру. Клиенту ничего не отправляется.
- Страница `GET /mock`: простая HTML-страница, имитирующая чат сделки. Сообщения клиента и менеджера уходят в тот же вебхук в amo-формате, примечания показываются под диалогом.
- Допродажи не повторяются: правило в промпте «не предлагай то, что менеджер уже предлагал в истории» и фильтр кодом, исключающий товары из прошлых подсказок по этой сделке.
- `httpx` переходит из dev-зависимостей в основные.

**Входит в прототип:**
- вебхук, разбор amo-формата, роли, дедуп, фоновая генерация;
- история и примечания в памяти процесса;
- mock-режим с HTML-страницей — основной способ демонстрации;
- `AmoCrmClient`, проверенный тестами с подменой HTTP-транспорта, и инструкция по подключению реальной amoCRM в `design.md`.

**Сознательно не делается:**
- отправка сообщений клиенту: Chats API (amojo) и Salesbot — ответ всегда черновик в примечании;
- проверка на живом аккаунте amoCRM (его нет), OAuth-авторизация с обновлением токенов;
- постоянное хранилище истории и примечаний; загрузка истории чата из amoCRM;
- распознавание товаров, которые менеджер предложил своими словами (поле `aliases` в базе) — только правило в промпте;
- запись в кастомные поля сделки, задачи, смена этапов.

## Capabilities

### New Capabilities
- `crm-dialog-adapter`: вебхук в amo-формате, определение ролей, дедупликация, история диалога по сделке, фоновая генерация только на сообщение клиента, формат примечания, интерфейс `CrmClient` и режимы `mock`/`amo`.
- `mock-chat-ui`: HTML-страница, имитирующая чат сделки, и эндпоинт чтения диалога и примечаний сделки в mock-режиме.

### Modified Capabilities
- `upsell-hints`: добавляется исключение товаров, уже предложенных по этой сделке (кодом), и правило для модели не повторять то, что менеджер уже предлагал в истории.

## Impact

- Новый код: модули адаптера (разбор вебхука, хранилище диалогов, `CrmClient` и две реализации, форматирование примечания), HTML-страница mock-чата, новые эндпоинты в `app/main.py`.
- Изменения: `ReplyService.reply` и `filter_upsell` получают необязательный список исключённых товаров; правило в системном промпте. Контракт `POST /v1/reply` не меняется.
- Настройки `.env`: `CRM_MODE`, `WEBHOOK_SECRET`, `AMO_SUBDOMAIN`, `AMO_ACCESS_TOKEN`. Токен amoCRM — секрет, в репозиторий не попадает.
- Зависимости: `httpx` в основных; новых пакетов нет (form-urlencoded разбирается стандартной библиотекой).
- Внешняя система: в режиме `amo` — REST API amoCRM; в mock-режиме внешних вызовов нет, кроме модели.
