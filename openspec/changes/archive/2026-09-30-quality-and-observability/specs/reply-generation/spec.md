## MODIFIED Requirements

### Requirement: Эндпоинт генерации черновика
Система SHALL предоставлять `POST /v1/reply`, принимающий JSON `{message: string, history: [{role, text}]}`, где `role` — одно из `client`, `manager`, `bot`, `system`. Ответ MUST содержать поля `client_reply`, `manager_hint`, `used_kb_ids`, `needs_human`, `reason`, `upsell`, `compliance`, `kb_version` и валидироваться Pydantic-моделью. `client_reply` MUST быть непустым. Сообщение, состоящее только из пробельных символов, MUST считаться пустым.

#### Scenario: Вопрос, на который есть ответ в базе
- **GIVEN** в базе есть FAQ `faq_delivery` со сроками и стоимостью доставки
- **WHEN** клиент присылает «Сколько стоит доставка в Казань?»
- **THEN** ответ 200, `client_reply` содержит сведения о доставке из базы, `used_kb_ids` содержит `faq_delivery`, `needs_human=false`, `reason=null`

#### Scenario: Некорректный запрос
- **GIVEN** работающий сервис
- **WHEN** приходит запрос с пустым `message` или неизвестной ролью в `history`
- **THEN** ответ 422 с описанием ошибки валидации, модель не вызывается

#### Scenario: Сообщение из одних пробелов
- **GIVEN** работающий сервис
- **WHEN** приходит запрос с `message`, равным `"   "`
- **THEN** ответ 422, модель не вызывается

### Requirement: Безопасный ответ при ошибке модели
Если модель отказалась отвечать, ответ обрезан по лимиту токенов, не прошёл валидацию схемы, вызов превысил `LLM_TIMEOUT_SECONDS` или вызов API завершился ошибкой после повторов, система SHALL вернуть ответ 200 с шаблонным `client_reply`, `needs_human=true`, `reason=other`, пустыми `upsell` и `used_kb_ids` и пометкой о сбое в `manager_hint` с видом сбоя, а также записать ошибку в лог. Таймаут MUST выделяться в отдельный вид сбоя `timeout` и не смешиваться с `api_error`. Число повторов вызова задаётся настройкой `LLM_MAX_RETRIES` (по умолчанию 0, без повторов). `LLM_TIMEOUT_SECONDS` по умолчанию 300.

#### Scenario: API модели недоступен
- **GIVEN** клиент модели выбрасывает ошибку соединения
- **WHEN** приходит запрос `/v1/reply`
- **THEN** ответ 200, `client_reply` равен шаблону, `needs_human=true`, `reason=other`, `manager_hint` сообщает, что черновик не сформирован

#### Scenario: Модель отказалась отвечать
- **GIVEN** модель вернула отказ вместо ответа
- **WHEN** сервис обрабатывает ответ
- **THEN** ответ 200 с шаблонным `client_reply`, `needs_human=true`, `reason=other`

#### Scenario: Таймаут модели
- **GIVEN** модель не ответила за `LLM_TIMEOUT_SECONDS`
- **WHEN** приходит запрос `/v1/reply`
- **THEN** ответ 200 с шаблонным `client_reply`, `needs_human=true`, `reason=other`, `manager_hint` сообщает, что черновик не сформирован из-за таймаута (`timeout`)

#### Scenario: Повторы по умолчанию отключены
- **GIVEN** `LLM_MAX_RETRIES` не задан
- **WHEN** сервис создаёт клиента модели
- **THEN** клиент делает не больше одной попытки, и запрос ждёт не дольше `LLM_TIMEOUT_SECONDS`

#### Scenario: Сбой модели, когда вопрос ещё и вне базы
- **GIVEN** клиент спрашивает о том, чего нет в базе, а модель недоступна
- **WHEN** сервис обрабатывает запрос
- **THEN** возвращается шаблон сбоя с `reason=other`, а не `no_kb_answer`: без ответа модели сервис не знает, есть ли ответ в базе
